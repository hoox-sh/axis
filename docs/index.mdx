# AXIS Documentation

**AXIS** is an installable charting PWA (v**2.24.5**, `package.json` / `VERSION`) that treats **price**, **time**, and **calculation** as separable axes. Release history is `CHANGELOG.md` ([online changelog](/axis/docs/changelog)). Sources load history. Streams advance the present. Engines evaluate Pine Script™ via **PYNE**. Storage keeps your script library. Compose any lawful combination without a proprietary charting host.

## What's new

The current **2.24.5** build — full detail in the [changelog](/axis/docs/changelog):

- **Agents can read and drive the live plane over MCP** — eight new `app_invoke` capabilities: `chart.lag` (the "why is the chart a bar behind?" ledger with `live` / `one-bar-behind` / `behind` verdicts), `chart.bars` (bounded OHLCV windows plus a gap map and forming-bar flag), `engine.get` / `engine.series` / `engine.tick` / `engine.repair`, and `stream.get` / `stream.reset`. Every engine call reuses the active endpoint and key in-tab — the key never leaves the browser and is reported as `hasApiKey` only. See [MCP (agents)](/axis/docs/enduser/guides/mcp).
- **The HP plane is observable over MCP** — `hp.get` (flags, cross-origin isolation, the `hp · sab+gpu` chip, hot-ring window/alignment/`seq`, GPU overlay state, verdict) and `hp.sample` (windowed ring-publish / frame-cadence / chart-append measurement). Pure reads — no flag writes, no wire start, no SAB allocation. See [HP engine](/axis/docs/architecture/hp-engine#mcp-observability).
- **Engine-owned live stops lagging** — the venue's forming tip survives every engine repaint (no bar chopped off the tail), a frozen engine series is repaired instead of back-dating the chart, a superseded engine socket can no longer tear down the connection, and the stream plane now drives the engine's series itself (10s cadence, new venue bars immediately). See [engine-owned data plane](/axis/docs/devops/engine-owned-data-plane).
- **The browser engine runs the PYNE 0.6.12 wheel** — the same release as the Pro API, including the `chart.point.copy` argument fix, numeric multi-return UDFs, and interpret/compile `fill()` parity. See [engine plugins](/axis/docs/plugins/engines).

## Abstract

AXIS is a charting PWA, not a language rewrite. Language fidelity lives in [PYNE](/pyne/docs). The PWA contributes:

1. A **unified plugin registry** (`source | stream | engine | storage | dataset | component`)
2. A **Solid + Vite** product UI (chart, editor, results, manager, Workers Manager, on-chain panel) with a **mobile-first responsive shell** and **global keyboard shortcuts** (recordable, persisted)
3. Optional backends: local Flask, offline Pyodide, Cloudflare® Worker (+ DO/KV/D1/R2 + `/api/onchain` proxy)
4. **AXIS CLI** + optional **Tauri** desktop shell for operators
5. **MCP** on the Worker (`POST /mcp`) so agents can drive APIs and a connected tab — [MCP (agents)](/axis/docs/enduser/guides/mcp)

**Invariant (AXIS ≠ engine):** the shell never embeds a closed interpreter. Evaluation is always an engine plugin.

## Demo topologies

- Dev: Vite `:3000` + Flask `:5002` (`axis install` then `bun run dev`)
- Desktop: `bun run desktop:dev` (Tauri 2)
- Static: `bun run build` + `axis_pwa_server.py` `:8081`
- Worker: `axis dev worker` / wrangler on `:8787`
- Prod: `axis deploy` → Worker `worker-axis` (`https://worker.axis.hoox.sh`) + Pages `https://axis.hoox.sh`
